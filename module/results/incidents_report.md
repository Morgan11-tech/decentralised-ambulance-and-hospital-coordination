# Incidents used in the experiments

Generated by `experiments/export_incidents.py`. Every incident below is rebuilt exactly as the model received it (same generator, seed and loader). Seeds 101–130 (30 simulated days per setting). Full list: `results/incidents/incidents.csv`, one row per incident.

## How the incidents are made

* **Normal demand** = Twente's 2024 urgent volume, 23,238 A0+A1 dispatches a year [Tweede Kamer 2025, nr. 747] = **2.65 urgent calls/hour**. A2 calls are added in the national ratio (A0+A1 = 62.4% of A0–A2 [RIVM/VZinfo]), giving **4.25 calls/hour** in total. A load of 1.25× means 1.25 times that rate.
* **Number of calls per run is fixed** for a given load: rate × load × 28 h (4 h warm-up + 24 h measured), rounded. Every seed at the same load has the same count; what changes per seed is when, where and how urgent.
* **Arrival times** are spread uniformly at random over the run, which is the same as a Poisson process with that number of calls (no day/night pattern). So the hourly counts below vary by chance.
* **Urgency** is drawn per call from the national mix A0 2.3%, A1 60.1%, A2 37.5% [RIVM/VZinfo].
* **Location:** 75% near Enschede, Hengelo, Almelo or Oldenzaal (weights 5:3:2:1, ~2.5 km spread), 25% anywhere in the region `[ASSUMPTION]`. 'Urban' below = within 6 km of a city centre (the metric's definition), so some 'rural' draws count as urban and vice versa.
* **On-scene time, transport and hospital stay** are drawn in advance per call (seeded), so every mode gets the identical patients.
* **Model clock:** minute 0 is the start of the generated stream (`generate_incidents.BASE_TIME`), so the measured window covers a full 24 h of calls. Warm-up = minutes 0–240, measured = 240–1680.
* **Fixed on 2026-10-28:** earlier runs started the clock at each run's *first* call (on average 15 min into the stream at 1×, up to 43 min), which shifted the stream and left the last minutes of the measured day without new calls (4.23 vs 4.25 calls/h at 1×). All results were re-run after the fix.

## E4: urgent calls that fall inside the outage (1.25× load)

The outage starts at model minute 840 (10 h into the measured day). E4's outage metrics use the A0+A1 calls made during the outage and the 60 min after it.

With only a handful of urgent calls in each outage window, a p95 over that window is close to the single slowest call; that is why the E4 p95 values have wide spreads between days.

`results/incidents/incidents.csv` — 78,570 rows, one per incident per (load, seed). Columns:

| Column | Meaning |
|---|---|
| load, seed | demand level and simulated day |
| used_by | experiments that ran on this stream |
| incident_id | id within the run |
| created_min | model minute of the 112 call |
| phase, hour_of_measured_day | warm-up / measured / after; hour 0–23 of the measured day |
| code | A0 (arrest), A1 (life-threatening), A2 (urgent) |
| type, description | the schema record the voice-agent pipeline would produce |
| latitude, longitude, x_km, y_km | location (real and model grid) |
| area | urban (≤ 6 km from a city centre) or rural |
| on_scene_min, transport_needed, hospital_stay_min | pre-drawn patient outcomes |
